## 业务口径与文档歧义处理

1. `API.md` 列出了节点规则错误码 `40006`，但 `BUSINESS_LOGIC.md` §4.2 和 `TESTING.md` TC-EDU-01 明确要求预检不通过仍允许提交。本实现遵循后两者：保存 `auto_check_passed=0`，前后端显示预警，不拒收作业。`FINAL_REVIEW.md` 没有对此给出其他默认方案。
2. `edu_submission` 的 `(task_id, student_id)` 唯一约束表示每位学生每课题保留当前一份提交。重新提交覆盖快照并清除评分、评语、评分明细、批改时间，恢复待批改；前端要求确认后替换。打回重做清除评分，保留教师重做评语。
3. 学生只能查看所在班级的课题，只能提交本人创建或参与协作的工作流。公开权限不能替代作业提交权限。学生仅查看本人提交；教师仅管理本人课题及其提交；管理员可跨教师管理。班级筛选按课题的 `target_class` 精确匹配。
4. 截止时间已过但数据库仍为“进行中”的课题，在列表及状态筛选中计算为“已截止”；逾期提交继续接收，`is_late` 严格按提交时间是否晚于截止时间判定。归档课题拒绝提交。
5. 提交、批改、课题修改和删除使用课题行锁；提交还锁定工作流主表，与既有画布保存事务协调，防止读到混合版本。课题主从删除处于同一事务，测试验证父表删除失败时从表删除回滚。
6. 评分细则存在时，其名称须唯一、各项满分大于零、满分合计100；教师必须填写完整且不超项满分的得分，总分必须等于各项之和。无细则时允许仅总分评分。总分限制为0～100、最多两位小数。
7. 增加 `GET /api/v1/edu/tasks/{id}`，用于提交页读取单个课题，沿用相同权限和响应包装；未改变文档内已有接口。

## 统计口径

- 成绩分段、均分和及格率仅纳入 `review_status=1` 且存在成绩的提交；及格率分母是已评分数量。分数区间为 `[0,60)`、`[60,70)`、`[70,80)`、`[80,90)`、`[90,100]`。空样本返回0，避免 NaN。
- 趋势按数据库当前提交的 `submitted_at` 聚合；重新提交更新该日期，不虚构历史提交次数。调试与报错来自存在对应学生及工作流提交关系的 `SANDBOX` 运行，排除教师试跑、模板测试和未交作业用户的运行。采用 `EXISTS`，共享工作流或多课题提交不会重复计算同一次运行。数据库无任务与执行直接外键，因此同一学生工作流提交至多个课题时，该运行可归属于各课题；全局汇总仍只计一次。
- 五维雷达依次为：快照通过既有 DAG 拓扑校验的比例；LLM 节点同时配置系统提示与用户模板的比例；条件节点具备有效操作符、字段表达式及 true/false 两条分支的比例；已结束沙箱运行成功率；教师对名称含“报告”的评分项所给平均得分率。前两类配置指标衡量配置完整性，不代替教师语义质量评价。缺少可用样本的维度返回0。
